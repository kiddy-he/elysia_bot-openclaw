# OpenClaw 对外功能与权限配置

当前使用 `/root/.openclaw/onebot-features.json` 作为功能授权、身份和群聊范围的主配置。编辑器 Schema 位于 `config/onebot-features.schema.json`，运行时还会验证配置中的角色、账号、动作及群号引用。

业务入口已拆为多个专用工具，复用原有业务脚本；对话提醒由进程内固定处理器执行。业务操作、审批、附件和投递回执落入持久账本。投递统一委托 OpenClaw 原生持久队列，不再另建重试队列。Gateway 保留对话和角色编排，各业务权限由主配置独立控制。

## 身份与群聊

`reminders.create/list/cancel` 使用 `public` profile，向已准入会话的管理员、普通群友及私聊访客开放，爱莉和月下均可用，无需审批。提醒意图由入站分类的 `reminder_action` 判断，非关键词路由；只有本轮相应意图才开放创建或取消工具，取消时可先列出本人任务。默认北京时间；“明天八点”按明天上午08:00处理并明确确认日期时间，有其他歧义先问清。相对时间以入站消息时间为起点。支持未来一年内的一次性文本提醒，周期与后台任务仍走原管理权限。

`reminder_create` 只能绑定实际消息所在群聊或私聊本人。群内接收者可按账号昵称、群名片、QQ号匹配，采用归一化、部分匹配和编辑距离近似匹配；有接近的多名候选时要求确认，不向模型导出整群成员名单。到期程序发送真实 `at` 消息段，正文内伪造的 CQ 字符串只是文本。`reminder_list/cancel` 仅处理本人、同账号、同会话的任务；已开始发送时不能虚报取消。每人最多100条未完成提醒，同一条原始消息最多一条提醒；多角色收到同一消息时也不重复创建。提醒正文不作为新指令执行。

提醒保存于业务 SQLite 的 `reminders` 表，后台每5秒检查一次；重启后继续处理，超时不超过24小时可补发。到期重新检查权限和目标是否仍在原群，并以固定编号进入原生持久队列；回执不明确时不另建发送任务。功能配置升级可先运行 `node scripts/reminders-config.mjs` 预览，再加 `--apply` 备份并写入新增模块与执行器。

TTS 仅向爱莉希雅（default账号）开放，管理员、普通群友、私聊访客和已登记的爱莉自动任务均可按需使用。月下等其他角色在工具可见性、调用授权、任务能力及投递检查中均被禁止。使用本机爱莉扩充权重与 `elysia-light-v1` 后处理；不会开放 guest 通用 Shell、任意文件或跨会话投递。

明确语音请求先区分语音回答和原文朗读。`tts_synthesize` 在执行层检查Unicode字符数（含标点和英文字母）：最多200字；超过则不合成，记录完整文字与超限说明，网关强制发送完整文字，不删减或分段绕过。同一消息仅登记一个语音工作流。内置tts和固定脚本捷径不能代替专用工具。

未明确要求语音、也未拒绝语音的爱莉正常回复，以30%概率在生成正文前选中追加语音：本次LLM同时生成完整正文和最多40字的简短追加句。每回合独立随机标记绑定该短句，网关移除标记、先发正文，随后审查、合成并发送追加句；随机决定不由模型执行，不另开LLM创作追加句。短句超限、缺失、格式异常、权限失效或审查不可用时仅发正文。已登记的爱莉 agent 自动任务也通过生成前指令和发送成功回调使用同一追加策略，发送失败时不追加。

guest明确请求的原文/答案及随机追加句，以及自动任务发往群聊的语音，均先由无记忆、无工具的 Gemini 3.5 Flash Lite 独立审查角色一致性、内部信息与可能的色情隐喻/性暗示。仅所有审查项明确通过才合成；拒绝、格式异常、接口错误或超时均不生成。确定的内部路径、密钥和控制标记还会提前拒绝。原文朗读不豁免，不允许改写被拒绝文本重试；拒绝文本不作为语音或拒绝回执原文回显。

合成与投递继续绑定当前消息、发送者、账号及自动任务登记目标。普通对话通过原生持久投递队列发语音，自动任务仅允许登记的 `speechTarget`；任务取消会中断合成。每日计划、启停状态和原始任务正文保持原配置。

QQ 私聊的文件下载回执可能被上游标成普通 `message/private` 文件消息。Gateway 在模型分类和批处理前，检查无正文且无可下载 URL／路径的文件占位消息：只有本账号与该私聊对象最近 100 条历史中，确有自己先前发送的相同文件 ID、文件名及大小时才静默忽略。此规则同时适用于两个账号的管理员和访客私聊；新文件、附带文字／引用的消息继续正常处理。历史查询最多等待 5 秒，失败时保留消息，不根据文件名或自然语言猜测系统回执，也不调用模型来识别回执。

- admin：仅 `identities.adminIds` 中的 QQ 用户。加入频道私聊白名单或拥有 QQ 群管理员头衔都不自动获得此身份。
- member：当前准入群聊中的其他成员。
- visitor：未在 admin 列表中的私聊用户。
- internal：Gateway 自己触发的角色接续，不来自用户自称或工具参数，不授予后台工具。

群聊 member 保留闲聊、媒体、引用、图片功能及单独 @ 一个角色后的额度查询/刷新。后台、模式修改、群聊会话重置仅 admin 可用。admin 在群里执行后台操作仍需明确选择一个角色。`conversation.mode` 目前整体按 admin 管理，包括模式状态命令。

2026-10-19 起，普通访客私聊不再限制每分钟接收或回复的轮次；同一会话沿用批处理和顺序队列。旧 `guestReplyIntervalMs` 配置仅兼容读取，已不参与对话限流，当前配置为 0。独立的访客图片生成冷却、权限、工具限制、工作区隔离、入站去重和投递限速保持生效。

`profiles` 定义身份、会话范围和是否必须单选角色。每个模块再指定 `groupIds`、`accountIds`，每个动作选择 profile。只允许显式声明的权限，不从昵称、引用作者、角色名或群头衔推断权限。

## 修改示例

只让 700000011 使用图片功能：

```json
{
  "features": {
    "images": {
      "groupIds": ["700000011"]
    }
  }
}
```

此片段表示修改现有字段，不能用片段覆盖完整配置文件。其他字段保留。

只允许 admin 生成图片：把 `features.images.actions.generate.profile` 改为 `owner`。停用某模块：将其 `enabled` 改为 `false`。暂停某个现有定时任务：修改 `automationBindings.<任务ID>.enabled`，然后执行同步。

```bash
cd /root/.openclaw/onebot-onebot-custom
npm run features:check
npm run features:matrix
npm run features:sync
openclaw config validate
```

- `check`：验证主配置、角色与账号关联、旧配置兼容镜像、当前定时任务启停漂移及目标群声明；只读。
- `matrix`：生成当前 admin/member/visitor 在各账号、群聊中的有效动作列表。
- `sync`：先备份，再同步 `onebot-role-routing.json` 的身份/群聊兼容字段、`openclaw.json` 的频道 allowFrom，以及已登记任务的启停状态。没有授权的新群不会因已有任务而自动放行。缺失任务或未知角色会拒绝同步。

动作权限和模块开关每次判定时重新检查，合法修改热加载；配置缺失、拼写错误或 JSON 损坏时拒绝权限，不回退为宽松默认值。新增账号、频道连接、角色本体仍需修改各自配置并重载/重启 Gateway。不要直接修改兼容镜像作为功能授权来源。

`onebot-app-config.json` 保留超时和批处理参数；`onebot-model-routing.json` 保留模型链；角色本体、公开人物摘要与名字仍放在 `onebot-role-routing.json`。这些配置职责不同，不合并密钥或私人记忆进功能文件。

非生图对话采用分阶段等待：普通对话 150 秒、图片分析 250 秒后汇报已确认完成的步骤，并继续同一次执行；默认总上限为 `extendedResponseTimeoutMs=900000`（15 分钟），之后只汇报未完成/结果不确定并终止本轮等待，不自动重做外部操作。后续每隔原等待时长更新进度，完成后汇总全部确认结果、失败项及剩余工作。群内固定额度查询/刷新分别在原 75/255 秒上限时汇报，使用相同总上限。进度只包含当前请求的固定步骤名称与确认状态，绝不转发原始工具输出、命令、路径、凭据、日志或思考过程；不绕过 guest 权限、审批、单个工具限时和定时任务独立预算。图片生成、编辑、参考图工作流继续使用原 60 分钟规则。

## 强制执行边界

1. Gateway 在固定功能入口检查模块、身份、群号、账号和动作。
2. 原生 `before_tool_call` hook 使用实际 OneBot 入站事件绑定的上下文。用户或模型提供的 senderId/isAdmin 不作为授权依据。普通成员不能使用 read、exec 或其他后台工具冒充固定额度/生图功能。
3. 文字、图片、语音和文件投递使用同一账号/目标群检查，禁止向未配置群投递。群聊定时通知还检查登记的投递群，不能意外切换到私聊或另一个群。
4. 原生定时任务在 `automationBindings` 中登记。执行 `sync` 后，停用模块会暂停对应任务。ALAS 巡检脚本和 Qzone 每日准备/动态一次性发布任务在运行前另外检查功能开关，避免 command payload 绕过 agent hooks。
5. 上述配置不取代现有多模型审批。允许调用某模块，不等于批准重启、修改核心配置、破坏性操作或未经授权的空间发布。

### 通用工具的保守限制

通用 exec/read/write 能访问多个模块，不能仅凭脚本名称或自然语言分类证明没有跨模块副作用。因此通用工具要求当前发送者同时具备全部可达模块的后台权限；限制任何一个可达模块后，通用 Shell/文件操作也会拒绝，防止通过 curl、临时脚本或 import 绕过模块关闭。

专用工具已覆盖 ADS-B、ALAS、Rewards、下载、空间、网络、额度、图片、定时任务和 Bilibili。可把某个只读动作的 profile 改为 group-public，向群成员委派该固定工具；其余模块和通用 exec/read/write 不会因此开放。成员图片保留固定入口与冷却规则。

内置 image_generate 在 OneBot 会话中禁用；专用入口是 onebot_image_generate，确保提示词优化、角色参考和图片质量复核不会被新版内置工具替代。图片身体结构评分、最多三次成功生图、都未达标时选最高分规则保持。

## 工作区与自动化

onebot-workspaces.json 登记 27 个新代理和 18 条路由。群聊按群号、角色、normal/nsfw 分开；私聊访客按用户分别建会话；公开自动化使用独立工作区。各公开角色的内部审阅、备用、改写、视觉和接续共用本角色的无工具 helper，但各次调用使用独立 session key。公开代理关闭跨会话记忆搜索，不预装私人资料。

公开代理不复制主代理的 heartbeat 字段，系统只保留原 main 的定期私聊 heartbeat；不会为公开 helper、访客或群聊派生后台心跳。原 admin 私聊及爱莉 Grok 私聊工作区、历史保留；月下 NSFW 私聊使用自己的新工作区。未复制历史群聊内容到新工作区，避免带入早期私聊摘要。私聊模式按账号加用户保存，两个机器人不会互相切换模式。

onebot-services.json 给自动化任务登记真实服务身份、固定 argv 和最小动作能力，不冒充 admin。14 个原任务保留 13 启用、1 停用；8 个公开提醒使用无工具 helper、toolsAllow=[]；Rewards 汇报使用公开 main 且只允许 rewards_summary。私聊 heartbeat 保持原归属；3 个 command 任务经 run-scheduled.mjs 再验授权。纯提醒创建顺序为“禁用创建→登记授权→明确空工具权限→启用”，避免未登记窗口。

注意：当前版本 CLI 的 --tools 空字符串表示未指定，会回退为 [*]，不能用于禁用工具。代码通过 cron.update 显式设置 toolsAllow=[]。每日说说未来的一次性任务也经登记和固定服务包装；仍每日一次、08:00–22:00 随机，保留当日去重与质量规则。

每日空间图文按**计划发布的北京时间**选择上午、午间、下午、傍晚、晚间主题，文案、活动、服装、场景和光照同时受时段约束；例如“夜灯下写日记”只在晚间候选主题中。草稿检查拒绝用回忆昨夜等说法绕过当下时段。原图片身体结构质量评审后，再单独查看实际成图，检查光照、作息、图文活动与计划时间，生成绑定图片、文案、场景及日期/时段哈希的 `.time.json` 证据；不达标时不进入发布，走已有当天随机重试与失败通知。身体评分三张选最高规则不覆盖时间检查。

生成延迟只能在同一时段内重新随机安排；跨时段则重新准备。发布在上传前和实际发帖前两次校验时段，避免排队拖延后错时发送。已发布和结果不确定的记录仍按原去重/核对规则处理，不因本次规则更新而重发。固定准备任务与随机重试预算为 4800 秒，重试仅继承其固定脚本所需的参考图能力，不开放通用生图或后台工具。

## 操作、审批与投递

state/business/operations.sqlite 保存操作、审批、依赖、附件与每个发送分片的回执。专用工具只接受固定动作参数；同一入站请求重复模型调用使用同一业务操作，不会反复收费生图。写操作超时记为 uncertain，先核对后处理，不能通过换调用 ID 自动重做。

控制工具沿用多模型审查；网络、ALAS、空间写入和自动化管理需要与发送者、会话、账号及完整参数绑定的一次性人工确认。Bilibili 订阅修改按用户明确要求无需审批，仍仅 admin 可调用，且群聊只能管理本群。确认持久保存，Gateway 重启后仍可引用原确认消息继续；无关聊天可正常回复。开启模块不是批准其全部写操作。

所有 OneBot 文字、图片、语音、文件及脚本告警通过原生持久投递接口。每个 producer 使用稳定去重键，模型不决定投递身份和目标。临时附件先持久保存；按账号／目标限速，默认全局最多 2 并发；平台接收回执落账。发生“可能发出但未取得回执”时保留不确定状态，不盲目重发。原生队列是唯一传输重试方，不启动第二个重试 worker。历史未确认发送不会因迁移重放。

ALAS 脚本调用 scripts/deliver.mjs，经本机 loopback、Bearer 验证及固定服务／目标白名单进入同一队列。群聊附件只允许本次业务产物、本次入站附件或本群工作区文件；不会通过模型输出任意本地路径来发送。

## Bilibili

接入 Akokk0/bilibili-notify 的通用 webhook：校验 secret、时间戳、固定 targetId 路由，接受动态、直播、文字、合成图文和卡片链接；来源事件去重后使用同一原生队列。外部传入的 private/group 字段不能改变预配置目标。图片内联附件持久保存，不下载任意外部 URL。

生产监控已运行，群 700000012 已接入 UID 700000010、700000001。`bilibili_subscribe` 支持按 UID 添加或取消 dynamic/live/all，默认两项；群号由可信会话绑定，私聊 admin 必须指定已授权群。上游订阅、关注和分群事件目标自动同步，支持不同群订阅同一 UP；取消只撤销本群选定事件，不取关，不删除其他群路由。添加和取消均无需审批。`bilibili_status` 只展示目标群的实际同步状态，真实通知是否送达仍由投递回执证明。部署及故障恢复见 integrations/bilibili-notify/README.md。

## 运维与验收

```bash
npm run modular:check
npm run modular:status
npm run modular:gc
npm run check
npm run test:simulation
```

check 验证工具合同、服务登记、工作区及定时任务漂移；status 查看业务账本状态。gc 默认只预览；加 --apply 才清理保留期外、无引用且已确认接收的附件，不清理不确定项。

模拟器启动隔离 OpenClaw Gateway、假模型和假 OneBot，使用独立配置、账本和合成人物资料。它覆盖不同用户、群聊准入、单选／多选角色、引用、额度、图片、备用模型、normal/nsfw、审批重启、所有原定时任务的克隆以及脚本／Bilibili 投递。控制、图片、额度脚本均由明确的模拟 preload 替代，真实 QQ 消息与业务写操作为 0。权限矩阵另覆盖全动作、身份、群、账号和撤权组合。

验收日志放在 state/modular-implementation-20261016，权限为私有；模型调用记录仅包含模拟上下文。真实服务另做状态查询及已授权额度刷新检查。模拟通过不等同于真实上游可用性、真实网络故障下恰好一次发送或 Bilibili 登录验收。

最终验收：111 项插件测试、36 项图片策略测试、19 项空间测试及 55 个对话／自动化场景通过。详见 /root/openclaw-handoff/modular-tools-acceptance-20261016.md。隐私审计按实际请求的可信 Runtime agent/session 归属，不以异步执行期间可变化的测试名称判断；原始和修订报告均保留。
