# AGY 额度请求的语义分类

更新日期：2026-10-22。

群聊额度请求复用已有入站 LLM 分类，不再使用额度关键词、正则或 `/agy` 命令捷径识别请求，也不新增单独的分类调用。普通模式沿用 antigravity/gemini-3.5-flash-lite；隔离对话模式沿用其现有分类提供商。

分类字段 `quota_action`：

- `query`：查询当前额度，映射为固定脚本的 `quota` 子命令。
- `refresh`：刷新并返回剩余额度，映射为固定脚本的 `refresh` 子命令。
- `none`：本轮不是可由固定额度操作完整处理的请求。
- 字段缺失、非法或模型失败在本地变为 `unknown`，不回退到正则识别或默认刷新。

“刷新agy额度并检查还剩多少”分类为 `refresh`；“不要刷新agy额度”“解释刷新agy额度是什么意思”分类为 `none`。未来提醒、逐字朗读和混合独立任务不应被额度处理器截取。解析后的生图、小红书、逐字朗读或提醒任务标记也会阻止额度处理器接管。

执行仍要求真实事件来自群聊、明确选择单个角色、非角色间追问，并通过现有 quota.query / quota.refresh 权限检查。没有扩大身份或群聊范围；当前额度群聊配置为 700000008 和 700000011，700000012 不开放。始终以运行时权限配置为准。模型输出和用户原文均不能成为 shell 命令或任意参数。

分类后的固定处理器在执行前检查取消状态，沿用进度通知、超时、固定参数执行和输出字段过滤；提前返回时清理本轮语音临时文件。脚本结果解析、输出脱敏和通用权限检查的格式规则仍保留，这些不负责识别额度语义。

验证：相关单元测试覆盖模型到固定操作、身份和群聊限制、非法分类与失败、取消信号传递、固定 argv、结果过滤及错误不泄露。实际分类接口的 8 个样例均通过：原失败消息、查询、`/agy refresh`、功能讨论、否定操作、混合重启任务、未来提醒、逐字朗读。本次实际接口验证只调用分类器，没有执行刷新或向群内发送测试消息。
