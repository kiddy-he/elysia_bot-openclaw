# 主模型与备用模型的会话上下文

主模型和备用模型共享同一主会话中的对话事实。每轮在取得该会话的处理锁后，通过 OpenClaw SDK 的可见分支读取接口生成一份固定历史窗口；主代理通过 `before_prompt_build.appendSystemContext` 接收该窗口，回复检查和所有备用尝试接收同一个字符串。窗口按最近消息优先选择、恢复时间顺序，默认限制为 24,000 UTF-8 字节，另附已有的已提交摘要；不再独立执行旧的 12 条 / 单条 1,500 字符截断。

这统一的是对话记录与本轮共享窗口，不是两家提供商的服务端缓存。主代理仍有其原生长期历史、工具调用和工作区系统指令，备用代理保留较窄的工具权限和自己的终审指令；完整请求包并不逐字相同。

## 输出提交

生成的主代理无工具调用的助手候选，通过同步 `before_message_write` hook 标记为 `provider=openclaw/model=gateway-injected` 的审计记录，保留原始内容、用量、错误信息及原始模型出处。OpenClaw 核心不会把这种记录重新提交给模型。含工具调用的助手消息和工具结果保持原样。

只有收到 QQ 平台消息 ID 且没有失败或 suppressed 标记的最终文字，才通过 `appendSessionTranscriptMessageByIdentityStrict` 写入正式的 `provider=onebot/model=conversation-delivered` 助手消息。文本使用发送层返回的 `renderedText`，包含实际完成的人设改写和称呼清理。写入绑定确切 sessionId，具有以会话、请求和投递回执组成的幂等键。会话重置不会将旧回复写入新会话；回写失败只报告日志，不重复向 QQ 发送消息。

不能使用普通 `delivery-mirror` 替代正式助手记录：该类镜像会被核心从模型输入中排除。

主模型候选摘要不再提前保存。正式主回复确认送达并提交后才更新摘要。备用替换不提交主模型的候选摘要；它保留此前已确认的摘要，并用共享正式记录补足当前回答。

## 范围和限制

- 覆盖主回复、文本/读图备用回复的最终文字、快速媒体工作流的最终文字；进度通知不作为最终答案提交。
- 群聊不同发送者、私聊与角色继续使用现有隔离的会话身份。
- 历史记录不做破坏性重写；部署前缺失的备用答案不会凭空恢复，旧摘要也无法保证此前已经准确。新机制从启用后持续建立可追踪的一致记录。
- 不改变模型路由、拒答判定、解析器、安全边界或权限设置。
- 纯语音回复使用受信任 TTS 成功业务记录中的原始合成文本和已接受投递回执，标为 `[语音]`；随机语音追加收到平台回执后以 `[语音追加]` 记录。不会从模型声明臆造发送成功。
