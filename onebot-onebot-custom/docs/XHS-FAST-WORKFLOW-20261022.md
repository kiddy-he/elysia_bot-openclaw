# 小红书批量工作流提速与验收（2026-10-22）

目标：从消息入站到 QQ 合并消息取得发送成功回执约 60 秒。此次已实现、部署并重载服务；没有删减每帖图片或绕过权限、挑战验证、文件校验和真实发送回执要求。

每帖独立节点，第一个段为【帖子标题】，随后为该帖全部图片；所有帖子只有一条合并消息，回复文字另发。两轮真实测试对应严格60000ms阈值为一轮通过、一轮超出3秒，不能宣称全部小于60秒；对于“约60秒”的目标，当前常规样本已达到29–63秒范围。视频、超大图集、复杂语义选帖、共享账号或同群投递排队、上游延迟/验证不保证60秒。

历史生产参考样本分别为151.297秒（3帖10图）、173.225秒（3帖14图）。这些与新样本不是同一组帖子，不作为严格控制变量的压测对照。

发图前主模型规划均仅**1轮**，其后主模型整理文字不计入发图耗时。首轮最终文字56.286秒，第二轮107.412秒；这次以合并媒体回执为目标，尚未全面压缩最终文字审查/改写链路。

## 改造

新增 `xhs_media_workflow`（OneBot适配层工具，不改变小红书上游API合同）。模型一次优化搜索词、确定数量和排序，宿主接管搜索→批量详情核对→逐帖取句柄→完整图集下载→后台任务等待→逐帖暂存→一次合并发送。避免以前各下载、状态、暂存步骤之间重复等待模型。模型主链路不变，语义判断仍由模型完成，无消息关键词匹配。

- `query` 与 `ref_ids` 二选一。query自动搜索12条可见候选；高赞rank=likes仅比较候选的可用点赞数，不声称全站排名。普通relevance，最新latest；图片image或视频video。
- 默认3帖，范围1–3。复杂语义筛选可先用搜索/详情选定，再交ref_ids。明确要求超过3帖使用低层兼容链，不擅自缩减数量。
- 沿用read/media权限，目标只取真实入站会话。两个机器人账号、admin与guest、私聊与已配置群聊均可用，无审批。没有新增登录、凭据或平台互动写权限。
- 每个上游步骤使用原有共享账号FIFO，排队与执行共享180秒工作流总期限。轮询为本地任务查询，等待间隔释放FIFO；等待下载与QQ上传不会占用上游队列。
- 下载/暂存失败不发送残缺批次；清理本工作流新产生的暂存选择，防止最终回复的自动flush意外发出部分帖子。真实461，包括批量详情嵌套461，立即终止，沿用原有受控恢复流程。
- 仍由原持久队列、去重键和真实QQ回执控制发送。不确定投递结果不会自动重复上传。工具返回真实投递状态、所选帖子和各步骤耗时，便于后续审计。

实现：`src/src/features/xhs-workflow.js`、`features/xhs.js`、`features/tools.js`；同步catalog、manifest、执行器默认项、入站工具约定、进度标签及已安装skill/项目skill副本。
