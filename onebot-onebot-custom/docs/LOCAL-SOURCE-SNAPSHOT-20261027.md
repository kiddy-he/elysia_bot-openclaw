# 本地源码归档与详细变更说明（2026-10-27）

本次将当前可维护源码、测试、集成适配器、部署工具及说明统一纳入本地 Git。先前仓库只跟踪了部分基础插件文件，大部分业务模块尚未跟踪；因此本次同时归档最新功能及其完整依赖，而不是仅提交孤立的新模块。

## 本次重点：定时任务与聊天记录双向互通

| 部分 | 修改 | 结果 |
| --- | --- | --- |
| `src/src/destination-context.js` | 新增 SQLite 可见消息存储、目标解析、窗口投影、任务提示词 hook、历史补录与重置边界 | 同目标聊天和定时任务共享已实际出现的消息 |
| `src/src/gateway.js` | 记录获准入站消息；读取目标历史并加入共同历史窗口；重置成功时设置读取边界 | 保留成员独立线程，同时理解本群公开提醒 |
| `src/src/conversation-transcript.js` | 成功提交最终回复时补记目标可见记录 | 实际送达的主模型、备用或语音说明可以延续到后续聊天 |
| `src/src/outbound.js` | 在 OneBot 成功回执后记录实际文字分片 | 未投递草稿、失败和不确定状态不会冒充已发送消息 |
| `src/src/channel.js`、`src/src/delivery/queue.js` | 将经过验证的持久投递来源、工作区和会话信息传到传输层 | 出站消息按实际账号、目标和模式归档 |
| `src/src/features/reminders.js` | 保留提醒创建时的工作区信息 | 普通定时提醒维持模式归属并继续原文发送 |
| `src/index.js` | 注册定时任务上下文 hook | 已注册的模型型任务执行时自动获得目标窗口 |

隔离规则：群聊按群号和模式分区，同群公开消息可供已配置角色参考；私聊按机器人账号、对象和模式分区。不会把私聊、其他群或不同模式的记录合并到当前目标。历史是只读、不可信资料，不授予工具或执行权限。

保存边界：每个目标/模式最多 1000 条、7 天；新增提示词窗口最多 60 条、12000 UTF-8 字节。原有单会话共同实录窗口保持自己的上限。普通聊天主模型和 fallback 共用同一份固定快照；一次定时运行重复构建提示词时复用该次快照。

初始化仅导入精确匹配目标/模式的 clean input 与带投递回执的助手记录；正常模式且没有已记录的模式切换时，可通过 OneBot 只读历史接口补充近期文字，单次请求最多 4 秒。重置边界优先于补录，不恢复重置前历史。既有旧 grok 工作区不导入。

本地四条提醒的提示词同时更新，允许参考系统提供的本群近期可见记录，并继续禁止私聊、其他群、凭据和私人记忆。任务执行状态、运行数据库和实际聊天内容不归档到 Git。

## 脱敏与 Git 范围

`prepare-sanitized-git.py` 使用允许列表生成提交副本，随后写入 Git 暂存区；不改写在线程序、账号标识、权限配置和登录状态。`git diff` 中仍可能显示在线文件与提交中的脱敏示例不同，这是预期状态，不能直接用 checkout/reset 覆盖生产配置。

- 真实 QQ、机器人、群标识及服务任务 UUID 统一替换为稳定示例值，跨源码、测试和配置保持一致。
- 内网地址改为文档示例地址；自定义上游域名改为示例域名。部署路径及回环接口保留，用于理解本机运行方式。
- 配置凭据使用环境变量占位符；模型提供商保留 SecretRef 结构，不包含密钥文件内容。
- 配置快照清空历史会话迁移清单；验收 JSON 中的实际回执、用户名、验证码相关值移除，保留聚合结果与时间指标。
- 测试中的两个字母序列虚构 key 用于验证脱敏逻辑，明确属于合成测试数据。
- Cookie、账号库、浏览器 profile、二维码、私聊/群聊原文、凭据、数据库、日志、媒体产物、缓存、依赖和服务实际 `.env` 不提交。
- 运行时插件构建副本与对应源码同步归档。本次安全复核发现运行目录中的 WebSocket 调试脚本曾携带真实访问令牌。修正时将该脚本从归档排除，并替换最末一条本地归档提交；更早的 7 条提交保持不变。

不要将归档中的示例配置直接覆盖在线环境。恢复到其他机器前，应填写实际身份、服务目标、SecretRef 与网络端点。

## 2026-10-27 凭据复核修正

最初的“真实凭据为 0”验收结论存在漏检：`extensions/openclaw-onebot/dist/src/ws-probe.mjs` 的 WebSocket 查询参数曾包含实际 OneBot 令牌。该脚本现已从提交范围排除，本机调试副本改为读取环境变量；运行中的令牌、账号和服务配置不变。

修正增加以下检查：HTTP/HTTPS、WS/WSS、代理及数据库 URL 的鉴权参数和用户密码；已知本机凭据的原文、URL 编码、Base64 和 JSON 转义形式；已跟踪但被归档策略排除的文件必须从暂存区移除。SecretRef、环境变量占位符和公开接口的固定参数不视为凭据值。

脱敏回归测试覆盖此次漏检和跟踪文件移除行为。归档最终文件树、提交差异和可达历史另进行凭据比对；本机原始审计数据不进入 Git。替换提交后清理该旧提交的 reflog 引用及其独有的泄漏对象，防止仅删除文件而保留可恢复版本。

## 2026-10-27 历史隐私与配置隔离修正（以本节为准）

为清理先前仅 HEAD 脱敏而旧历史仍含真实身份的问题，本地可达历史统一重写，真实身份和私有 provider 域名使用示例值；旧提交对象和 reflog 的残留同时清理。此前“更早提交保持不变”的记录描述修正前状态，已由本次修正替代。

所有版本中的根目录 `openclaw.json`、`onebot-*.json` 从源码归档移除。在线文件仍保留在原位置，Git 不再跟踪；不要 checkout/reset 覆盖在线环境。`config/examples/` 的 13 份配置由固定的通用模板生成，不读取实际账号拓扑，不包含秘密文件路径、实际端口、共享目录或现用账号路由。它们仅展示字段结构，并非可直接部署的完整配置；`${EXAMPLE_*}` 表示部署时必须填写的值，不代表所有上游配置读取器都支持自动变量展开。

后续仍使用 `prepare-sanitized-git.py --output <新的仓库外目录> --stage` 归档。新增 `check-sanitized-index.py` 检查暂存区全部文件，拒绝根目录在线配置、状态和凭据文件、真实本机身份/凭据、私有 provider 域名及被修改为在线拓扑的示例模板。当前机器安装了本地 pre-commit hook；新克隆必须运行 `python3 onebot-onebot-custom/scripts/check-sanitized-index.py --install-hook` 安装。hook 是防误操作机制，可被 `--no-verify` 等显式绕过，不是权限隔离。

本次没有更换在线令牌、重启服务或推送仓库。源码中通用的功能接口、部署约定和本机工具路径不等同于实际在线配置，仍可在业务代码或文档中出现；本次隔离的是实际部署配置及真实身份/provider 信息。对外发布前仍应按发布范围做复核。
