# 每日空间图文的本地角色参考方案

每日入口仍为 `scripts/qzone-daily.mjs prepare`。每天 06:15（Asia/Shanghai）准备，08:00–22:00 随机发布一次。脚本随任务启动读取配置，无需重启网关。已经准备或发布的日期不自动重画。

## 两层随机

配置：`scripts/qzone-character-policy.json`。

1. 先按 `interactionProbability` 决定互动，当前为 0.5。
2. 单人模式仅在爱莉希雅目录内均匀随机选择一张图。
3. 互动模式先枚举有可读取 PNG/JPEG/WebP 的角色目录，排除爱莉、空目录、损坏文件头、符号链接和超大文件；按角色权重选一位同伴，再从双方目录内各均匀随机选一张图。图片数量不影响角色被抽中的权重。
4. 无同伴参考图时回退单人并记录 `soloFallback`；无爱莉参考图时失败并进入原有恢复流程，不静默在线找图。

当前可选同伴的权重总和为 100：伊甸 30、芽衣 25、帕朵菲莉丝 15、梅比乌斯 10、符华 8、阿波尼亚 6、格蕾修 6。数值是依剧情关系设置的创作偏好，不是官方亲密度。将来已有配置的空目录补图后，自动按其配置权重参与；新名字默认权重 3，可在配置中调整，设置 0 可排除。

## 文案、生图和验收

`qzone-characters.mjs` 保存每次人物方案。日期状态的 `referencePlan` 记录人物、顺序、路径和 SHA-256；重试准备会重新抽取。文案只接收人物姓名、关系提示和参考图编号，不接收本机路径或聊天记忆。双人文案必须提及同伴；场景必须含全部指定姓名。

计划发布时间、主题和人物方案一起传给 `qzone-draft.py`，由现有文案模型链生成活动文案与场景。场景要求每人有明确动作分工、表情、姿态、视线和空间关系。原图仅作身份与外观参考，动作、表情、姿态、镜头与构图均根据新活动重新设计，服装按活动与时段调整。

生图命令为 `agy-proxy-diagnose.sh local-image-generate <场景> <参考图...>`。底层支持 1–8 张参考图用于多人测试；每日选择器仍固定为 1 或 2 人。`local-reference.py` 只接受 `/root/letu_chara_image` 下的真实图片路径，图片以文件方式构建 Base64 请求，避免命令参数长度限制。Gemini Responses 编排、GPT Image 2 Edits 生图、视觉验收按相同顺序读取全部原图；原图不改写、不删除。备用 Responses 链也携带同一组图片。

原有身体结构 70% 权重、质量不通过最多重画两次、三张评分后择优例外、发布时间一致性复核、失败通知、随机重试、防重复发布均保留。质量验收会检查期望人数、全部角色、身份映射、活动动作、替换原姿态和场景导向的姿态/视线。评分属于模型判断，不能保证图像没有任何细微瑕疵。
