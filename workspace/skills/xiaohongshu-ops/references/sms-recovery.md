# OneBot 登录失效与连续 461 短信恢复

此流程由宿主负责，沿用项目 [SMS-LOGIN.md](/root/komachi-xhs-js/docs/SMS-LOGIN.md) 中已实现的短信登录。不是新增公开模型工具，不能通过 exec、read、write 或 xhs_* 参数传入手机号/验证码。

## 触发与人工操作

- 一次明确的 `login_required`（含详情/下载任务内嵌错误，或已停止请求中的同类登录错误）即可启动恢复；或15分钟内连续两个不同入站任务收到真实 HTTP 461 时，宿主创建一项共享账号恢复流程。`session_invalid`、权限拒绝及限流不直接请求短信。请求已停止后的本地 challenge_required、重复工具调用不重复计数。成功的上游内容读取会清除连续计数。
- 首次没有配置手机号时，默认爱莉通过私聊向当前配置的 admin 请求当前小红书账号的中国大陆绑定手机号。admin 引用这条消息只回复 11 位号码；宿主保存在仅当前用户可读的独立凭据文件，不进入模型历史。
- 宿主按 auto 选择 v1/v2，使用独立 pending 身份请求一次短信，然后另发 admin 私聊请求验证码。admin 必须引用这条验证码请求，只回复 6 位验证码，保留前导 0。手机号请求和验证码请求不可互换。
- 短信等待最多 10 分钟；共享流程最多每小时启动一次。发送接口接受不代表短信送达。不会自动重发，不在群里索取验证码，不换号或轮换代理。
- 仅默认账号发出的绑定请求、原私聊收件人且仍具 admin 权限的引用回复才可提交。认证回复在入站调试日志、模型分类、群历史和对话处理前截获。模型只得到待恢复状态，不能读取手机号、验证码、Cookie、登录身份文件或登录链接。

## 恢复原任务

宿主收到 authenticated=true 后，重新检查原发送者、原群聊/私聊、账号和功能权限，等待原对话任务退出，再在原会话恢复一次小红书任务。待恢复请求最多保存 30 分钟、最多 16 项；权限撤销、会话重置、超时取消均停止恢复。

只解除该用户和会话明确属于 `challenge_required` 或 `login_required` 的终止记录；只允许重试被验证阻断的读取和失败下载。保留成功读取缓存、原下载任务 ID、已暂存完整图集以及已发送/不确定/取消的记录。不能重发已有投递，不自动重新生成其他功能内容。恢复上下文只准使用小红书专用工具。

等待验证码期间重启可继续接受原绑定引用。短信发送/验证码提交途中重启，结果不明的步骤不重放；恢复对话执行途中重启也不盲目再次发送。验证码错误、短信接口返回 challenge_required/rate_limited 等会结束本次流程，需要管理员处理。登录后业务再次拒绝则停止，不进入自动重登循环。

## 模型应如何回答

收到 sms_recovery.status=pending 或 manual_verification_pending 时，告诉用户任务暂停，正在等待管理员完成登录；不要让普通用户提供验证码，不保证短信送达或任务已经恢复。

watching 仅表示挑战错误尚未满足连续两次真实 461 的条件，明确登录失效不等待此阈值；cooldown 表示恢复冷却中；blocked_after_login 表示登录后接口仍拒绝本任务。均应如实说明当前未完成，不增加调用来凑触发次数。

宿主恢复通知出现后，复用给出的已成功结果，完成未完成步骤。完整图集与合并消息规则保持一致。只有实际工具结果和 QQ receipt 能证明获取和发送成功。
