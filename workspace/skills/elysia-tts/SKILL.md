# 爱莉希雅本地 TTS

默认使用本机 `elysia_expanded_v1` 扩充权重与 `elysia-light-v1` 轻度双频带预设。固定参考、CPU/FP32、6 线程、seed=42；默认按中文句号 `cut3` 分段。完整调用说明位于 [USAGE.md](/root/GPT-SoVITS-local/local_deploy/USAGE.md)，仅在调整分段、排障、自定义参考或处理已知原始音频时阅读相应章节。日常合成不需要启动 9872/9874 网页、服务或重新训练。

## 请求语义与专用工具（仅爱莉希雅）

本功能仅供爱莉希雅使用（OneBot default 账号）。管理员、普通群友和私聊访客均可向爱莉提出请求；月下等其他角色不提供TTS，不借用或让其他角色代发。使用 `tts_synthesize({"text":"最终朗读文本"})`，身份和目标由网关绑定。

语音输出意图由消息先验分类模型在同一次任务分类中判断：`answer` 是先回答再转语音，`literal` 是逐字朗读，`disabled` 是明确拒绝语音，`none` 是普通聊天。不得依靠关键词或正则自行改变分类结果。分类失败或字段无效时只用文字，不随机追加语音；如用户要求语音，诚实说明这次未完成语音输出。定时任务在主模型执行前采用同一分类规则。

明确要求语音时，待合成的完整文本不得超过 **200 字**（按Unicode字符数，含标点和英文字母）；超过则说明超限并用文字发送完整答案，不删减、不拆分成多条语音绕过。工具返回 `textOnly:true` 时按 `notice + fallbackText` 或 `safeReply` 用文字回复，不再重试合成。QQ 会话中由工具在合成后直接投递到本条消息的原会话，不依赖模型输出 MEDIA；只有返回 `delivered:true` 才表示已经收到平台回执，不再发送附件、路径或 JSON。`delivered:false`、`textOnly` 或 `safeReply` 按返回的诚实文字回退处理，不宣称已发送、不重复合成。自动任务同样由程序投递。

未明确要求语音且未拒绝语音时，程序对普通回复以 **30% 概率**选中一条随机语音追加。在被选中的回合，你必须在**同一次模型回复**中完成正常正文和不超过 **40 字**的简短追加句，使用本回合系统指令给出的 `VOICE_APPEND` 随机标记。正文先正常发送，程序再合成追加句；你不调用TTS工具，不用第二次LLM调用另编一句，不输出追加句的MEDIA路径。未选中则不追加。标记是内部格式，不解释或显示给用户。追加句超长、缺失、格式错误或未通过审查时仅发正文。

guest（普通群友和私聊访客）的语音文本，包括明确指定的朗读原文和随机追加句，必须先通过独立审查。角色越界、舰长或过分亲昵称谓、内部信息、密钥/路径/工具细节、可能的色情隐喻、性暗示和诱导文字均不合成；不能因为“只是复读原文”豁免。审查不可用或无法确认安全时也不合成。不得改写被拒绝的稿件重试或绕过专用工具。

**先区分语音回答和逐字朗读：**

- “用语音告诉我／回答我：问题”“用语音解释／总结……”：先根据问题、当前会话资料和需要且已授权的业务工具完成正常回答，再将最终答案交给 TTS。问题本身不是朗读稿。例如“用语音告诉我：今天中午吃什么”，先给出具体午餐建议（有相关已知偏好时结合偏好），再合成这段建议；不能只念“今天中午吃什么”，也不能只说“好的”。如果当前身份不能完成资料查询，先形成诚实的权限或未完成说明，再按用户要求朗读，不绕过权限。
- “用爱莉的声线说一句：原文”“朗读／念／配音以下文字”“把这句话转成语音”：仅去掉外层指令和包裹引号，将指定原文作为 text；保留文字和标点，不加入前言、回答或角色润色。例如“用爱莉的声线说一句：今天你也很可爱哦”，text 必须为“今天你也很可爱哦”。即使指定原文是问句，也按朗读处理，不回答问句。
- “用语音说一句安慰我的话”等没有给定逐字稿的创作请求，先创作所需内容再合成。不要仅按冒号或疑问词匹配；按要求回答还是要求复述判断。确实没有提供可朗读文字或问题指向不清时，再简短澄清。

TTS 工具本身不会替你回答问题，只会在需要时调用独立审查模型检查 guest 稿件；text 必须已经是最终要说的话。工具报错时保留文字答案；随机追加仅按程序本次选择生成，不由模型自行决定概率。

## 本地合成入口（管理员诊断／本机执行）

短文本：

```bash
python3 /root/.openclaw/workspace/skills/elysia-tts/scripts/synthesize.py --text '今天也要记得好好休息。'
```

带引号或多行的文本优先写入本次任务自己的 UTF-8 文件，再执行：

```bash
python3 /root/.openclaw/workspace/skills/elysia-tts/scripts/synthesize.py --text-file /本次任务/要朗读的内容.txt
```

也可用 `--stdin` 从标准输入读取。文本限定为 1–200 字符；更长内容说明原因后完整转为文字，不删改或分段绕过。普通语音回复优先简短自然的中文；去掉 Markdown 和不应朗读的内部说明。角色语气与对方称呼来自当前对话，示例中的“舰长”不代表可用于 guest。此模型仅用于爱莉角色，不向其他角色开放。

脚本输出单个 JSON。仅 `ok:true` 时使用 `audio_output`：这是经过预设处理并校验的 32 kHz 单声道 PCM16 WAV。`raw_output` 是回退原音，`metadata` 与 `log` 为本地诊断文件，默认不发送。预设已包含降调、清晰度 EQ、双频带组合和静态响度匹配，**不要再次处理最终 WAV**。没有启用 FFT 降噪，也没有自动人工听审或逐字准确率保证。

使用渠道支持的后台 exec/process 等待完成，不因 CPU 推理较慢重复启动。固定执行超时 900 秒，同一入口只允许一个生成任务，忙时返回 `busy`；失败返回 `ok:false`，依据 `reason` 报告，保留文字回复，不把已有的 `.raw.wav` 或半成品宣称为成功成品。每次调用使用独立任务目录；显式要求重新生成时才新建调用。

## QQ 回复与投递

用户要求向**当前已授权会话**发语音时，合成成功后在最终回复使用渠道媒体指令（独立一行）：

```text
MEDIA:/root/.openclaw/state/tts/elysia/本次任务/speech.wav
```

将路径替换为本次 `audio_output` 的真实值。OneBot Gateway 将 `.wav` 作为 QQ 语音处理，并通过既有账号／目标检查和持久投递流程发送。不要另外直调 OneBot API、读取 token 或同时再发一次，避免重复投递。合成成功只证明生成完成，是否送达以渠道回执为准。

用户明确要求“文件形式”时，使用现有文件上传流程，保留 `.wav` 文件名；不要走上述媒体指令，因为当前 Gateway 会把 WAV 自动归为语音。跨会话或向 admin 等其他对象发送，须由已有授权的投递入口绑定账号和目标；合成脚本本身没有发送功能，不接受目标 QQ 参数。

此 skill 只新增固定 TTS 能力，不授予 guest 通用 exec/read/write、任意文件读取、其他后台工具或跨会话投递权限。群聊和访客应使用 tts_synthesize，不自行执行上述管理员诊断脚本。不要将私聊内容作为群聊配音；仅使用当前会话和已授权业务结果。正常群聊 @ 触发、账号开关和已登记任务的投递范围照旧。

## 检查

```bash
python3 /root/.openclaw/workspace/skills/elysia-tts/scripts/synthesize.py --check
```

只检查解释器、入口、模型、参考音和外部程序是否存在；不代表已完成推理。错误细节留在本地 `generation.log`；对 QQ 只说明失败结果和必要的下一步，不泄露路径、输入文本、模型日志或内部信息。需要进一步诊断时依 USAGE.md 检查本次 JSON 和日志，不启动训练或 IndexTTS。
